# Code Task Router（代码任务路由器）

## 概述

将代码任务按特征分派给「质量达标前提下性价比最优」的模型。路由器由任意 LLM 充当（母 Agent），执行模型按任务动态选择（子 Agent），同一会话内可横跨两个平台多款模型。

## 决策流程（四步）

### 第1步：难度分类

读取任务描述，按 L1~L4 标准判定难度并给出置信度：

- L1 入门级：单函数、短代码、常见API、无复杂逻辑
- L2 进阶级：多函数协作、完整类/模块、中等算法、基础业务逻辑
- L3 高级：复杂算法、系统设计片段、调试重构、多模块
- L4 专家级：框架级代码、分布式核心逻辑、疑难问题、高性能优化

置信度 < 0.7 时，难度升一档再决策（保守策略：高派一级只浪费钱，低派一级导致质量返工）。

### 第2步：候选筛选

读取 `references/model-registry.md` 中的模型档案，依次过滤：

1. 硬约束：隐私要求为「仅本地」时拒绝分派并明确说明（当前无本地部署模型）；单任务成本超预算上限的剔除；平台不可用的剔除
2. 质量门槛：该模型在对应难度级的质量分 ≥ 及格线（L1/L2=60，L3=65，L4=70）。低于及格线视为无法胜任该难度，再便宜也不选

### 第3步：排序与首选

- 有实测数据时：对候选模型计算 `S_value = S_quality / (Cost^α × Time^β)`（默认 α=0.65、β=0.25；成本敏感场景 α=0.8，时延敏感场景 β=0.4），取最高为首选。成本必须按实际输入长度查阶梯价（>32K/128K/256K 跳档）
- 无实测数据时（先验版）：按 `references/dispatch-rules.md` 的先验规则表选择首选

### 第4步：分派输出

取首选 + 备选链（排序中第2、3名，同分优先换平台），输出 JSON：

```json
{
  "primary": {"platform": "volcengine|aliyun", "model": "模型ID"},
  "fallback_chain": [{"platform": "...", "model": "..."}],
  "decision": {"difficulty": "L?", "confidence": 0.0, "estimated_cost": 0.0, "reason": "一句话决策依据"}
}
```

## 回退协议

首选模型生成结果未通过质量校验（语法检查 + 单元测试）时，按序执行：

1. 换备选链下一模型重试，任务包中回传上次失败信息（错误详情/未通过的测试）
2. 连续 2 个模型失败 → 跳过排序直接调用旗舰（doubao-seed-2.1-pro 或 qwen3.8-max）
3. 平台级故障（5xx / 限流 / 超时）→ 切换另一平台同梯队模型
4. 日累计成本达上限 → 熔断，仅用免费额度内模型或暂停并告警

## 并行模式（可选，默认串行）

- 竞速：同梯队双平台并行调用，取首个通过校验者（时延约×0.5、成本约×2）
- Best-of-2：跨梯队双模型并行，用单元测试或裁判选优（高价值任务）
- 生成-评审分离：轻量模型生成 + 代码专项模型评审，不过再升级（批量场景）
- 启用判据：期望质量增益 × 任务价值 > 增量成本；落选结果同样计费，成本按满额计

## 运行模式

1. **Prompt 模式（默认）**：将本文件作为系统提示词注入任意 LLM，由其充当母 Agent 执行四步决策
2. **脚本模式**：运行 `python scripts/route.py --task task.json`，纯规则确定性分派，零调用成本、结果可复现

## 数据层维护（关键原则）

模型档案与规则表是**可替换数据层**：新模型发布或实测数据产出后，仅更新 `references/model-registry.md` 与 `references/dispatch-rules.md`，本文件逻辑原样工作。当前为 v0.1 先验版（基于公开定价与能力定位的估计），评测完成后替换为实测数据版——这就是本研究「过程可复现、结论可刷新」设计的具体落地。
